# EVM Project Tool 0.1.0

## Resumen

Primera release de la capacidad **EVM Project Tool**: herramienta local de seguimiento de Valor Ganado (EVM) con persistencia PostgreSQL, API REST FastAPI, dashboard React y orquestación Docker Compose. Las cuatro unit-specs MakIA (`evm-project-tool-db`, `evm-project-tool-backend`, `evm-project-tool-frontend`, `evm-project-tool-infrastructure`) están en estado **Completado** con creación **Aprobado**.

Validación E2E pre-release: **PASS_CON_OBSERVACIONES** — infraestructura (compose up, migraciones, healthchecks), API (CRUD + indicadores CPI/SPI sin Infinity) y persistencia tras `down/up` verificados; la UI en navegador no se validó (browser MCP sin pestaña disponible).

## Cambios

### db (`evm-project-tool-db`) — PR #1

- Esquema PostgreSQL con tablas `projects` y `activities` vía `yoyo-migrations`.
- Integridad referencial: FK con `delete: cascade`, CHECK en porcentajes y montos no negativos, índice en `project_id`.
- Migraciones idempotentes (`yoyo apply --batch` re-ejecutable sin fallar).
- `lefthook.yml` en raíz para verificación local de backend y frontend.
- AUDIT: **PASA**.

### backend (`evm-project-tool-backend`) — PR #2

- API REST FastAPI hexagonal bajo `/api/v1`: CRUD de proyectos y actividades.
- Cálculo de indicadores EVM en lectura (PV, EV, CV, SV, CPI, SPI, EAC, VAC) e interpretaciones CPI/SPI; valores nunca persistidos.
- Dominio: `Project`, `Activity`, value objects `ProgressPercentage` y `MonetaryAmount`, `EvmCalculationService`.
- Infraestructura: repositorios PostgreSQL (psycopg3), schemas Pydantic v2, CORS, Swagger UI en `/api-docs`.
- 53 tests, ~99 % cobertura en `domain/` + `application/`; `ruff` limpio.
- AUDIT: **PASA**.

### frontend (`evm-project-tool-frontend`) — PR #3

- Dashboard React/Vite/TypeScript (React 19, Vite 8, Recharts 3) como capa de presentación sin lógica EVM en cliente.
- Componentes: `ProjectSelector`, `ConsolidatedIndicators`, `ActivitiesTable`, `PvEvAcChart`, `CpiSpiBadge`, `ActivityFormModal`, CRUD completo de proyectos y actividades.
- Cliente HTTP tipado alineado con OpenAPI backend (10 métodos REST).
- Dockerfile multi-stage + `nginx.conf` para servir `dist/` estático.
- AUDIT ciclo 2: **PASA** (correcciones H-01..H-04: CRUD proyectos, anti doble-submit, formato nulls).

### infrastructure (`evm-project-tool-infrastructure`) — PR #4

- Docker Compose V2 en `apps/infrastructure/`: servicios `db` (PostgreSQL 18) → `migrate` (yoyo one-shot) → `backend` → `frontend`.
- Un solo comando `docker compose up` para primer arranque y arranques posteriores (migraciones idempotentes).
- UI en `http://localhost:8080`, API/OpenAPI en `http://localhost:8000`.
- `.env.example` versionado; reset documentado con `docker compose down -v`.
- AUDIT: **PASA_CON_OBSERVACIONES** (4 notas menores, no bloqueantes).

### docs — PR #5

- `README.md` con instrucciones de arranque del stack completo desde `apps/infrastructure/`.
- Artefactos MakIA de la idea `evm-project-tool` (viability, draft, learning, db-design) y specs de las 4 unidades incluidos en la promoción a `main`.
