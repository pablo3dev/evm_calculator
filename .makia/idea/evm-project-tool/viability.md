# Title
Viabilidad — EVM Project Tool (registro de avance y cálculo de indicadores de Valor Ganado)

# Veredicto
SI

# Justification
El dominio (Valor Ganado / EVM bajo estándar PMI) está completamente formalizado en un lenguaje ubicuo ya existente en el proyecto (entidades, fórmulas, invariantes, sin ambigüedad). El alcance es 1 sola capacidad de negocio (N=1, no hay features independientes separables — todo gira en torno al ciclo crear proyecto → crear actividades → registrar avance/costo → calcular y visualizar indicadores EVM), pero es multi-unidad: su realización obliga a escribir código en 4 unidades con límites de despliegue/responsabilidad distintos y ya definidos por el propio requerimiento del usuario (`apps/db`, `apps/backend`, `apps/frontend`, `apps/infrastructure`, cada una con su propio stack, Dockerfile y responsabilidad — mover todo a una sola unidad rompería las fronteras de responsabilidad ya fijadas: "backend no debe delegar lógica de negocio al frontend", "frontend es solo presentación"). La investigación técnica (LEARN) confirmó que todas las piezas del stack elegido por el usuario son combinables entre sí sin bloqueadores duros: Python 3.14 (estable), FastAPI 0.141.1 (estable), uv 0.12.9, yoyo-migrations 9.0.0 (migraciones SQL puras, sin ORM), psycopg3 3.2.10 (driver PostgreSQL recomendado actual, con soporte de SQL parametrizado seguro contra inyección), PostgreSQL 18 (imagen Docker oficial, con `gen_random_uuid()` nativo y tipo `timestamptz`), React 19.3.0 + TypeScript 7.0.2 + Vite 8.0.10 + Node.js 24 LTS, y Docker Compose V2 con `depends_on: condition: service_healthy` para orquestar arranque ordenado — todo combinable sin conflictos de versión identificados. Existen 2 riesgos menores de evidencia incompleta (no bloqueadores) documentados en Evidence, mitigables durante IMPLEMENT.

# Evidence
- Python 3.14: versión estable 3.14.7 (release final 3.14.0 ya publicado), sin restricciones de compatibilidad encontradas. Fuente: python.org/downloads, PEP 745.
- FastAPI: versión estable más reciente 0.141.1 (PyPI). Docs automáticos configurables a rutas custom vía `FastAPI(docs_url="/api-docs", redoc_url="/swagger-ui")`. Fuente: PyPI, Context7 `/websites/fastapi_tiangolo`.
- uv: versión estable 0.12.9, con patrón oficial de Dockerfile multi-stage documentado (`ghcr.io/astral-sh/uv:python<version>-trixie-slim` + cache de BuildKit). Fuente: Context7 `/astral-sh/uv` y `/astral-sh/uv-docker-example`.
- yoyo-migrations: versión estable 9.0.0 (PyPI), soporta backend `postgresql+psycopg` (psycopg3) con sintaxis de migraciones SQL puras y comentario `-- depends:` para dependencias entre migraciones. Fuente: ollycope.com/software/yoyo, PyPI.
- psycopg3 (paquete `psycopg`): versión 3.2.10, patrón de pool (`ConnectionPool`) y ejecución parametrizada segura (`cur.execute("...%s...", (valor,))`) confirmado. Fuente: Context7 `/psycopg/psycopg`.
- PostgreSQL: imagen Docker oficial estable más reciente `postgres:18`; `gen_random_uuid()` nativo desde PG13; tipo `timestamptz` nativo. Fuente: hub.docker.com/_/postgres.
- React 19.3.0, Node.js 24 LTS ("Krypton", activo hasta 2028-05-31), TypeScript 7.0.2, Vite 8.0.10 (requiere Node 20.19+/22.12+, cumplido por Node 24). Fuente: registry.npmjs.org, nodejs.org, Context7 `/microsoft/typescript`, `/vitejs/vite`.
- Docker Compose V2 (`docker compose`, `compose.yaml`), `depends_on.condition: service_healthy`/`service_completed_successfully` para arranque ordenado db→migraciones→backend→frontend. Fuente: docs.docker.com/compose.
- Linter/formatter estándar confirmado: `ruff` (Python, versión 0.16.3, sustituye black+flake8) y ESLint 10.10.0 + Prettier 3.9.6 (TypeScript/React, estándar establecido con evidencia de fuente primaria vía npm registry). Fuente: PyPI, GitHub astral-sh/ruff, registry.npmjs.org.
- lefthook: sintaxis de `lefthook.yml` resuelta directamente contra la plantilla propia de MakIA ya existente en el proyecto (`.makia/core/harness/templates/lefthook.example.yml`), que confirma el campo `commands:` (no `jobs:`) con `root:`/`glob:`/`run:` por comando — sin necesidad de fuente externa adicional.
- Riesgo de evidencia incompleta 1 (no bloqueante): yoyo-migrations no declara `requires_python` en sus metadatos de PyPI y su último release es de agosto de 2024 (~2 años sin publicar); no se encontró confirmación oficial explícita de compatibilidad con Python 3.14, aunque tampoco evidencia de incompatibilidad. Mitigación: verificar instalación real contra Python 3.14 al inicio de IMPLEMENT de la unidad backend/db; si falla, escalar como evento de fricción (gap de `learning.md`).
- Riesgo de evidencia incompleta 2 (no bloqueante): no se pudo confirmar directamente el classifier exacto de Python 3.14 en los metadatos del paquete FastAPI 0.141.1 (Starlette/Pydantic v2 declaran soporte continuo de Python 3, sin restricción documentada encontrada). Mitigación: misma verificación real al inicio de IMPLEMENT.
