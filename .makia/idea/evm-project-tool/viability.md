# Title
Viabilidad — EVM Project Tool (registro de avance y cálculo de indicadores de Valor Ganado)

# Veredicto
SI

# Justification
El dominio (Valor Ganado / EVM bajo estándar PMI) está completamente formalizado en un lenguaje ubicuo ya existente en el proyecto (entidades, fórmulas, invariantes, sin ambigüedad). El alcance es 1 sola capacidad de negocio (N=1, no hay features independientes separables — todo gira en torno al ciclo crear proyecto → crear actividades → registrar avance/costo → calcular y visualizar indicadores EVM), pero es multi-unidad: su realización obliga a escribir código en 4 unidades con límites de despliegue/responsabilidad distintos y ya definidos por el propio requerimiento del usuario (`apps/db`, `apps/backend`, `apps/frontend`, `apps/infrastructure`, cada una con su propio stack, Dockerfile y responsabilidad — mover todo a una sola unidad rompería las fronteras de responsabilidad ya fijadas: "backend no debe delegar lógica de negocio al frontend", "frontend es solo presentación"). La investigación técnica (LEARN) confirmó que todas las piezas del stack elegido por el usuario son combinables entre sí sin bloqueadores duros: Python 3.14 (estable), FastAPI 0.141.1 (estable), uv 0.12.9, yoyo-migrations 9.0.0 (migraciones SQL puras, sin ORM), psycopg3 3.2.10 (driver PostgreSQL recomendado actual, con soporte de SQL parametrizado seguro contra inyección), PostgreSQL 18 (imagen Docker oficial, con `gen_random_uuid()` nativo y tipo `timestamptz`), React 19.3.0 + TypeScript 7.0.2 + Vite 8.0.10 + Node.js 24 LTS, y Docker Compose V2 con `depends_on: condition: service_healthy` para orquestar arranque ordenado — todo combinable sin conflictos de versión identificados. Los 2 riesgos menores de evidencia incompleta que existían sobre compatibilidad de yoyo-migrations y FastAPI con Python 3.14 quedaron confirmados (compatibles) mediante validación manual del USUARIO — ver Evidence; se conservan solo puntos de atención operativos (no riesgos) para IMPLEMENT.

# Evidence
- Python 3.14: versión estable 3.14.7 (release final 3.14.0 ya publicado), sin restricciones de compatibilidad encontradas. Fuente: python.org/downloads, PEP 745.
- FastAPI: versión estable más reciente 0.141.1 (PyPI). Docs automáticos configurables a rutas custom vía `FastAPI(docs_url="/api-docs", redoc_url="/swagger-ui")`. Fuente: PyPI, Context7 `/websites/fastapi_tiangolo`.
- uv: versión estable 0.12.9, con patrón oficial de Dockerfile multi-stage documentado (`ghcr.io/astral-sh/uv:python<version>-trixie-slim` + cache de BuildKit). Fuente: Context7 `/astral-sh/uv` y `/astral-sh/uv-docker-example`.
- yoyo-migrations: versión estable 9.0.0 (PyPI), soporta backend `postgresql+psycopg` (psycopg3) con sintaxis de migraciones SQL puras y comentario `-- depends:` para dependencias entre migraciones. Fuente: ollycope.com/software/yoyo, PyPI.
- psycopg3 (paquete `psycopg`): versión 3.2.10, patrón de pool (`ConnectionPool`) y ejecución parametrizada segura (`cur.execute("...%s...", (valor,))`) confirmado. Fuente: Context7 `/psycopg/psycopg`.
- PostgreSQL: imagen Docker oficial estable más reciente `postgres:18`; `gen_random_uuid()` nativo desde PG13; tipo `timestamptz` nativo. Fuente: hub.docker.com/_/postgres.
- React 19.3.0, Node.js 24 LTS ("Krypton", activo hasta 2028-05-31), TypeScript 7.0.2, Vite 8.0.10 (requiere Node 20.19+/22.12+, cumplido por Node 24). Fuente: registry.npmjs.org, nodejs.org, Context7 `/microsoft/typescript`, `/vitejs/vite`.
- Docker Compose V2 (`docker compose`, `compose.yaml`), `depends_on.condition: service_healthy`/`service_completed_successfully` para arranque ordenado db→migraciones→backend→frontend. Fuente: docs.docker.com/compose.
- Linter/formatter estándar confirmado: `ruff` (Python, versión 0.16.3, sustituye black+flake8) y ESLint 10.10.0 + Prettier 3.9.6 (TypeScript/React, estándar establecido con evidencia de fuente primaria vía npm registry). Fuente: PyPI, GitHub astral-sh/ruff, registry.npmjs.org.
- lefthook: sintaxis de `lefthook.yml` resuelta directamente contra la plantilla propia de MakIA ya existente en el proyecto (`.makia/core/harness/templates/lefthook.example.yml`), que confirma el campo `commands:` (no `jobs:`) con `root:`/`glob:`/`run:` por comando — sin necesidad de fuente externa adicional.
- yoyo-migrations 9.0.0 + Python 3.14 (CONFIRMADO, validación manual del USUARIO): compatible — yoyo-migrations está escrita principalmente en Python puro, por lo que no sufre por la falta de extensiones binarias (C extensions) que suelen romperse en versiones nuevas del intérprete. Punto de atención operativo que se mantiene abierto para IMPLEMENT (no es un riesgo de IDEA): verificar que el driver `psycopg` (3.2.10, ya elegido) soporte Python 3.14 en la instalación real de las unidades `evm-project-tool-db`/`evm-project-tool-backend`, y usar siempre la versión estable más reciente de yoyo-migrations en PyPI al momento de IMPLEMENT (para evitar advertencias de deprecación). Fuente: validación manual del USUARIO (no una fuente documental externa nueva).
- FastAPI + Python 3.14 (CONFIRMADO, validación manual del USUARIO): FastAPI es totalmente compatible con Python 3.14 a partir de sus versiones recientes (0.135.4 y superiores, incluyendo soporte para entornos de subprocesos libres/free-threaded Python) — la versión ya fijada en este proyecto, `0.141.1`, cumple. Requisito obligatorio derivado de esta confirmación: FastAPI ha eliminado por completo el soporte de Pydantic v1 (no compatible con Python 3.14); es obligatorio usar Pydantic v2 en `apps/backend/` (ya reflejado como decisión cerrada en `draft.md`). Punto de atención que se mantiene abierto para IMPLEMENT: prestar atención a extensiones de terceros con código C que puedan no estar adaptadas todavía a Python 3.14. Fuente: validación manual del USUARIO (no una fuente documental externa nueva).
